# 遮挡字幕文字

在主工具栏点 **遮挡字幕文字**，或选 **视图 → 遮挡字幕文字**。首次使用时关闭；开启后，即使换稿或重启也会保持。再次点击即恢复全文。这个开关独立于视频的「防剧透遮罩」。如需快捷键，可在快捷键设置里给 `subtitle/text_mask` 绑定一个未占用的按键。

例如，普通字幕行 `{\i1}别去，B2！\N{备注}` 中的「别去」和「B2」会被实心块遮住，逗号、叹号、换行符和两段花括号内容仍可见。遮挡以原文排版为准，不是把整行换成相同宽度的方块。你可以定位逗号、改成问号再保存，不必先看清台词。

- 网格、编辑区、原文对照和翻译助手（含正在输入的译文）都遮正文；样式助手、拼写检查和卡拉 OK 的字幕文字也受此开关控制。
- 光标、选区、搜索、撤销仍针对真实文字。**删除色块就是删除原字；复制、保存和导出得到的是原文。** 操作系统的输入法候选窗、剪贴板历史和其他程序不受此开关控制。
- 只遮未标为注释的行。角色名、样式名、时间码以及花括号内的所有内容（包括人为写入的备注）可能仍会透露信息。
- 视频预览只处理字幕稿的叠加层。当前版本的实时预览没有逐字形坐标，因此开启遮挡时预览只显示原画面、不叠加字幕层，并在视频框下方提示；截图、复制和导出仍使用正常字幕渲染。片源里烧录的字已经是像素，仍须使用独立的视频「防剧透遮罩」。
## 已在真实界面核对的部分

用 Arial、含 W i C 中 、 ! ? 的样例在真实桌面运行核对了以下行为：

- 网格、编辑区与原文对照同时遮挡；、!? ( ) [ ] , : 以及 {\i1}、{\b1} 标签保持可见。
- 注释行完全可读，不受开关影响。
- 切换前后编辑器的真实文本完全一致，W i C 中 、 ! ? 的横坐标逐个相同，说明遮挡没有改变原排版。
- 只把 ! 改成 ？ 后保存，磁盘上的字幕文件里是该真实字符而不是色块。
- 配置里预先打开时，启动的第一帧就是遮挡状态。
- 翻译助手的「原文」区、样式助手的「当前行」区同样遮挡。
- 视频预览：遮挡时画面只剩原视频、没有字幕叠加层，并在视频框下方显示提示；关掉后画面与开启前完全一致。

以下两处没有做像素级核对，只由代码路径与新增单元测试支撑：卡拉 OK 分字栏、音频时间轴上的音节标签。它们复用同一套字符范围与绘制逻辑，但本次测试环境没有对应的音频工程样例。
### 交互层实测（真实桌面）

- 复制：遮挡开启时执行「编辑 → 复制行」，剪贴板里是完整真实台词（含 \`{\\k20}\` 等标签与中文），不是色块。
- 撤销：在遮挡状态下把 \`!\` 改成全角 \`？\`，再执行「撤销」，编辑器文本回到原文。
- 查找：遮挡状态下打开「查找与替换」，搜索 \`End!?\` 能命中，选中位置与真实文本里的字节偏移一致（48）。
- 拼写检查器：错词框、替换框与候选词列表全部显示为实心块。
- 性能：3000 行、含中文与标签的字幕，加载约 1.4 秒，切换遮挡约 0.5 秒。

### 未取得实测证据的一项

工具栏按钮：图标已确认出现在主工具栏末尾，与 \`default_toolbar.json\` 中 \`subtitle/text_mask\` 的位置一致；但本次自动化环境里的鼠标点击无法送达该控件（同一时刻点击「新建字幕」按钮也不响应），因此「点击按钮即切换」这一步没有实测证据，只有它与菜单项绑定同一个命令这一事实。建议首次使用时手动点一次确认。

音频波形上的音节标注与卡拉 OK 分字栏同样仍未取得截图：卡拉 OK 模式只能由工具栏按钮开启，而该按钮点击在本环境不可自动化。
